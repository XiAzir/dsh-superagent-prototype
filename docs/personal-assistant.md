# 个人助理：目标、承诺、记忆与持续跟进

本模块在现有 Router、Worker、Ticket、Effects 与 Outbox 上运行。使用同一个 SQLite 数据库，schema 升级到 12。启用前建议按现有部署流程备份状态目录；旧版程序遇到新版 schema 会拒绝打开，应恢复配套备份后再运行旧版。

## 启用与身份

构建并重启加载插件的 DSH 实例，在个人模式打开 **Superagent → 个人助理**。功能默认关闭；启用后配置时区、免打扰时间和摘要间隔。

所有者账号默认 `web:owner`。QQ 使用 `qq:<用户ID>`；飞书使用对应来源的账号标识。账号还需要出现在该来源的允许名单中。个人记忆工具仅接受本人的原始私聊请求；Web 入口沿用服务端 owner 身份。普通群消息保持现有任务处理方式。

停用个人助理保留历史，暂停新的个人协调、提醒投递和个人模式工单复查。重新启用后，到期复查按原授权检查后继续。全局暂停保留已排定事项。停止某个工单会撤销它的复查和待执行行动；独立承诺保持自己的完成或取消状态。

## 目标、承诺与约束

- **目标**：记录期望结果、成功标准与优先级。
- **承诺**：记录责任人、等待对象、截止/预计/复查时间，关联目标与工单。
- **约束**：记录时间区间、单笔预算、隐私与渠道要求。时间和预算提案可通过冲突检查工具核对，结果附原始约束和来源。

开放承诺需要至少一个时间点。到期后进入注意力队列；每次复查记录后安排一天后的下一次检查，直到用户或 Router 更新计划、完成或取消承诺。若工作需要自动检查外部状态，Worker 通过下述工单复查安排执行。

## 工单复查

Worker 的 `orchestrator_report` 支持 `completed`、`pending`、`waiting_for`、`evidence` 和 `next_check`：

```json
{
  "state": "waiting",
  "summary": "资料已整理，等待供应商报价。",
  "completed": ["核对需求与订单编号"],
  "pending": ["收到报价后核对交期"],
  "waiting_for": { "kind": "external", "subject": "供应商报价" },
  "next_check": {
    "key": "vendor-quote",
    "at": "2026-11-07T09:00:00+08:00",
    "purpose": "检查原邮件线程",
    "success_condition": "收到包含价格和交期的正式报价",
    "resume_instruction": "读取最新回复；已完成步骤沿用已有结果，登记证据并更新后续安排。"
  }
}
```

日期必须带时区。相同 key 与相同内容重放保持幂等，修改时间或内容产生下一版本。每个工单最多 100 个待发复查。到期后，系统在原 Worker 空闲、授权有效时保存一个稳定编号的内部输入，通过原 Session 继续。停止、完成、失败或转为等待人工决定时取消待发复查。

## 可纠正的个人记忆

Router 通过 `orchestrator_personal_record` 记录事实候选，页面提供确认、撤销、编辑和删除。事实包含来源、生效与失效时间、适用场景及替代关系。Worker 默认读取与当前工单关联的目标/承诺，以及 `global` 或 `ticket:<id>` 范围内已经确认且当前有效的事实和约束。

新事实替代当前事实时，在一个事务内更新双方状态。删除事实会清除个人记忆表及其历史中的正文并留下最小删除审计；原始聊天、工单报告与备份按各自保留策略管理。

## 提醒与受控行动

P0 立即提醒，P1 遵守免打扰时间，P2 延至摘要窗口，P3 保存在工作台。相同摘要键的待发事项分批合并。关联工单的提醒送至原始 owner 私聊渠道；无可用渠道的事项留在工作台。只有 Outbox 保存送达回执后，提醒才标为已发送。

当前注册的受控外部行动为 `ticket_reply`：向工单已有渠道发送指定正文。Worker 先准备完整请求；页面展示目标、正文、风险和有效期。用户点击 **批准并发送** 后，后台执行并根据持久送达回执核实。授权绑定完整请求摘要，重复执行复用原结果。每次实际投递前再检查授权、工单和功能状态。

其他外部服务可通过 `ActionAdapter.execute/verify` 接入。此版本的行动账本覆盖已注册适配器；DSH 原有通用工具继续使用其现有权限配置。邮件、付款和日历等专项适配器需要按实际服务补充并验收。

## 验证与上线观察

模块冒烟与阶段回归覆盖存储迁移、CAS、来源授权、时间与静默策略、工单复查、精确审批、Outbox 回执、重复提交及真实子进程强制终止。测试使用临时数据库和模拟来源。

启用后的首轮真实验收建议选三个低风险任务：一个带明确期限的承诺、一个等待外部事件的工单、一个需要确认的短回复。核对时间线、下一次检查、停止和最终证据。工作台的分类计数、承诺状态、提醒和行动历史可以用于记录每周漏跟进、重复提醒、事实纠正和主动结果采纳情况；模型费用继续在 DSH 现有用量界面查看。

完整实施与测试记录见 [实施计划](personal-assistant-plan.md)。
