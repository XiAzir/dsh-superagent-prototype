# 验收与独立监督的查看入口

现有任务群、Worker 卡片、完整执行会话、消息定向输入、R 开关和停止操作保持可用。新增信息直接放在当前任务及已有执行设置分组中。

## 任务与 Worker

工单详情、任务群与原生右侧协作群显示验收方式与状态：等待验收、正在验收、验收通过、待修正，以及证据不足或暂未确认。状态同时带文字与图标，选中的详情区域通过一处语义状态区播报变化，避免所有 Worker 卡片同时播报。

“观察验收”记录独立意见；卡片尚未读取具体观察结果时只标明这一方式。点击“查看验收依据”后按需读取当前结果，展示成功条件、逐项检查、证据引用及历史验收。观察结果来自独立历史投影，原任务的生命周期保持现有行为。

“验收通过后交付”显示强制验收的当前进度。待修正项会沿后端既有修正流程交回原执行成员。对于证据不足、临时错误或需要重新检查的结果，可以点击“重新验收”。同一次失败重试沿用原 requestId；操作成功后，下次明确重验使用新的 ID。

验收详情或重验接口失败时，错误与重试按钮显示在验收区域；任务正文、交付物、消息输入和原有控制继续保留。资源额度或环境导致任务暂缓时，区域显示原因，并提供“恢复任务”入口。

## 配置

在“设置 → 执行”的原有执行参数之后，增加两个小面板：

- 成果验收与修正：关闭、观察验收、验收通过后交付，以及自动修正次数上限 0～3。
- 独立任务监督：观察并记录，或启用有界纠偏与持续停滞暂停；下方按需展开最近监督记录与证据。暂停保留目标、授权与会话，owner 检查后使用原恢复入口。

验收配置保存后用于之后接单的任务，进行中的任务保留其已捕获的方式。两个面板各自保存、反馈错误与重新读取，一项接口故障保持其他设置可用。

## API 与验证

界面使用现有 `Api` 类型和调用器：`GET tickets/:id/verification`、`POST tickets/:id/verify`、`POST tickets/:id/resume`、验收配置及 Watchdog 配置/历史接口。详情关闭时直接使用任务投影，避免为每张卡片额外拉取历史；展开后按 4 秒间隔刷新。新任务切换使用独立组件身份，过期请求结果会被丢弃。

专项覆盖：

- `tests/panel-verification.spec.tsx`：pending→passed、unknown 重验、稳定 requestId、接口局部故障、观察结果、配置作用范围、原任务群控件、资源恢复。
- `tests/worker-panel-ui.spec.tsx`：原生卡片 pending→passed，保留 R、消息输入及完整会话入口。
- 原 `panel-rooms`、`panel-execution` 回归保持通过。
- `tests/locales.spec.ts` 校验双语文案完整性。

运行示例：

```powershell
node node_modules/vitest/vitest.mjs run tests/panel-verification.spec.tsx tests/worker-panel-ui.spec.tsx tests/locales.spec.ts --pool=threads --maxWorkers=1 --reporter=dot
```

实现沿用既有语义颜色与控件，新增操作使用 44px 最小点击高度、可见标签、键盘焦点与按需展开。此次验证基于 DOM 与模拟 API；线上实例和用户正在执行的任务保持原状。

## 远端执行设备与结果核实

同一执行设置分组可以登记设备标识、名称、服务地址和已保存凭据的引用名。连接时由主机解析引用，登记表单提供的字段与设备列表均围绕引用管理。保存成功后清空登记输入，列表支持检查连接并展示离线原因。

工单详情的“执行环境与命令状态”按需展开。任务群中相同入口位于原执行详情页签的各 Worker 下方。选择已登记设备后，可以明确切换该任务的执行环境；服务端拒绝切换时保留当前工单和所选目标。命令列表展示设备、稳定命令 ID、实际状态、保留的输出及取消入口。

结果待核实的命令提供人工核实表单。用户先填写实际观察到的依据，选择完成、失败或取消，再核对设备、命令 ID、目标状态和完整依据后确认记录。请求包含检查时的 updatedAt，状态变化导致的拒绝会保留依据与现场，供重新核对。人工结论与设备原始记录同时展示，后续可以更正核实记录。

执行设置还展示实际任务效果汇总，费用与判断覆盖缺失时明确显示“未知”。工单详情提供独立的采纳、正确性和路由纠正反馈，失败重试复用原请求 ID。

`tests/panel-remote-environments.spec.tsx` 覆盖登记引用、离线探测、绑定失败保留现场、unknown 核实确认与失败恢复、费用未知及反馈幂等。`tests/autonomy-runtime.spec.ts` 使用真实 Runtime、SQLite、HTTP 与本地 daemon 验证设备工具接线、同命令重放、离线取消、未知结果 CAS、记忆更正、观察验收和效果反馈。

执行设置追加路由覆盖复核的关闭、观察、自动恢复模式，并展示当前预算。工单详情按需展开原请求、责任人及转交历史；其余 Worker 控制继续保留。模式、责任和恢复次数见[路由恢复](routing-recovery.md)。
