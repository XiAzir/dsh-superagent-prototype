# 个人模式与 Web 交办任务

本分支在上游 `deepseek-ai/dsh-superagent-prototype` 的基础上维护，保留原有
Router、Worker、任务调度、会话恢复和工单记录，加入个人使用入口。

## 直接在工作区新建会话

在 Superagent 工作区（对应配置的 `stateDir` 目录）点击「新会话」，新对话会自动显示
Superagent 模式。发送的原始用户消息进入同一套接单和派工流程，worker 的结果与需要确认的
问题会回到当前会话。继续发送消息即可追问、补充要求或停止任务。

每个对话拥有独立的任务线程。插件重载后会重新接入已加载的会话，并补录待处理的用户输入；
重复投递按消息 ID 去重。「设置 → 来源」中的「Superagent 会话」可控制此入口。
其他工作目录和 worker 子代理保留各自的运行方式。已有对话会在后续运行时获得接入能力；
DSH 已锁定的旧会话模式标签可能继续显示创建时的名称。

## 主 Session 的长期记忆

主 Session 共享一套持久记忆；新建对话仍通过主 Session 读取和维护相关主题。
每次请求只加载最多 3000 字符的主题目录，正文通过 `orchestrator_memory_read` 按需分页读取。
Worker 和普通会话入口的提示词保持精简，由主 Session 在派工时传递相关事实。

适合保存用户长期偏好、项目约定和经过核实的环境信息。每个主题记录标题、摘要、来源、
更新时间和版本；临时进度保存在工单中。更新前先读取当前版本，使用
`orchestrator_memory_save` 的 `expected_revision` 防止覆盖其他更新。更正时说明依据，
失效主题设为 `archived`，恢复时再保存为 `active`。历史版本始终可按版本号查询。

记录位于 `stateDir/orchestrator.sqlite` 的 `memory-topic:*` 和 `memory-version:*` KV 中，
随状态数据库一起备份。常用维护方式是直接在会话中要求“记住这项约定”“更新这个主题”
或“归档这条过时信息”。凭据继续由凭据服务管理。

## 左侧工作区视图

个人模式在左侧“工作区”标题下提供 **DSH / Superagent** 两个切换项。DSH 显示原生工作区和会话树，保留搜索、菜单、排序及展开状态。
Superagent 显示置顶的主工作区与主对话，下方按任务归组执行成员的工作区和会话；同一个执行成员关联多个来源时合并呈现，其子会话随对应任务归组。
执行中的任务默认展开，历史任务默认折叠。点击会话打开原生对话，任务旁的详情按钮打开面板内对应任务。
切换项、各分组展开状态、搜索条件与 Superagent 树滚动位置保存在当前浏览器会话中。Ctrl+Alt+K / Ctrl+Alt+O 会切回 DSH 视图使用原生搜索或添加工作区。

## 对话右侧的协作群

在至少 1600px 的宽屏中进入 Superagent 会话，右侧自动打开「协作群」。其他尺寸可从右栏入口手动打开。上方为 Worker 任务卡片，展示
进行、排队、等待确认等状态、最新汇报和已完成步骤；下方按群聊方式展示 Router 派工、
Worker 汇报与成员协作。切换会话时，列表跟随当前会话；主 Session 展示整体协作情况。

选择成员可筛选动态；卡片上的「@发消息」可以把补充要求直接交给该 Worker。展开步骤或
打开 Worker 会话可查看具体执行过程。收起协作群后，可以从右栏的添加页面入口再次打开。
窄屏保留手动打开方式。消息与任务状态自动刷新，阅读历史动态时保留滚动位置。

每个会话的提问携带独立消息编号。新会话查询已有工单的状态时，Router 将状态答复送回
提出问题的会话；任务最终交付继续沿任务的原始会话投递。面向其他会话的答复通过来源渠道
发送，主 Session 的调度窗口保持安静；直接在主 Session 提问时，回答留在主 Session。

## 打开

安装本分支的插件后，在 `dsh-superagent` 的机器配置中选择个人模式：

```yaml
- id: dsh-superagent
  config:
    mode: personal
    stateDir: C:/Users/your-user/.dsh/state/superagent
```

已有安装也可以从 **Superagent → 设置 → 部署 → 运行模式** 选择“个人模式”并保存。
模式变更会重启插件。配置好 DSH 的模型服务后运行：

```powershell
dsh --profile superagent
```

进入左侧 **Superagent**，默认打开 **工作台**。主导航为工作台、任务、个人助理和设置。
工作台汇总待处理事项与最近任务；任务列表统一展示各来源，支持搜索、状态与来源筛选、排序。
任务详情顶部展示最新汇报与交付物，下方通过对话、协作动态、交付物、执行详情切换视图。
点击“新建任务”即可交办，输入草稿与任务收件人随页面切换保留在当前浏览器会话中。
来源状态、消息接入、接单记录与执行记录可以从设置的运行管理入口访问。
本机部署的地址使用 profile 配置的端口，
当前维护安装为 `http://127.0.0.1:3082`。

任务群中的平级 Worker、协作订阅、定向输入和执行详情说明见 [任务群与协作](task-rooms.md)。

## 交办与追问

1. 在“新建任务”中描述目标，点击“开始任务”，也可使用 Ctrl/⌘ + Enter。
2. 系统保存对话，将消息以 `web` 来源的明确请求交给 Router。
3. Router 可以直接回答简单问题，或建立工单交由 Worker 执行。
4. 对话显示回复、工单状态与执行报告。需要继续时，在原任务下发送补充消息。
5. 关联工单可以打开执行详情，查看会话、重试或停止。

同一对话的消息使用同一个 Thread，后续消息可到达已经订阅它的 Worker。已完成的任务
可以通过新的补充消息继续，主动停止的工单遵循原有停止语义。

每条消息最多 16,000 个字符。发送失败时输入框保留正文，同一次发送的重试沿用请求编号，
避免网络重试创建重复任务。任务消息、回复、事件与工单保存在本地 SQLite 数据库中，
刷新页面或重启 DSH 后可以继续查看。

模型请求或执行回合失败时，任务页显示对应错误；新回合开始后清除旧错误。
主会话和 Worker 的失败信息分别从 DSH 会话事件恢复。

## 协作群

协作群采用左右布局：左侧是执行成员卡片，显示任务、状态和最新摘要；右侧在原位切换所选成员的阶段简述、协作对话与执行记录，两侧独立滚动。阶段简述按时间从上到下排列，可加载更早记录；阅读历史时，新动态通过提示按钮提醒。选择的成员、内容页签、阅读位置与未发送草稿会保留。

Worker 在完成阶段、获得重要发现、遇到阻碍及开始验证时主动提交简述。每次实际汇报后重新随机安排 5～15 分钟的总结提醒，计时持久保存。长工具调用期间保留一条提醒，在下一安全执行步骤总结已有事实；暂停、人类待确认和任务结束时停止自动催报。

输入 `@` 弹出成员列表，按名称或任务筛选，每次选择一位后收起，可再次输入 `@` 添加其他成员。标签只显示简短成员名。发送按钮旁的 R 开关蓝色表示交给调度助手：带 `@` 时由 Router 围绕指定成员统一安排；灰色时直达被提及的活跃成员。灰色且无成员时提示选择接收对象，已结束的成员由 Router 继续安排。

Superagent 的任务提交、追问及协作消息输入框均支持图片选择、粘贴和拖放，可以仅发送图片。每条最多 8 张，单张最多 10 MB，支持 PNG、JPEG、WebP 和 GIF；上传后可预览、移除及重试。原生 DSH 会话沿用已有图片输入能力。

## 模型与工作目录

Router 使用评估设置中的模型，Worker 使用执行设置中的模型；留空时继承 DSH 默认模型。
保存模型设置后，空闲会话立即更新；执行中的会话完成当前回合后使用新模型。重启时会按已保存设置恢复。
执行目录默认使用 `<stateDir>/work`，每个工单有独立目录。可以在 **设置 → 执行** 中选择
执行根目录、并发数和准备命令。Windows 使用 PowerShell 7。

个人模式的启动检查使用本地执行环境。GitHub、飞书的监听和专用账号配置归入仓库模式；
切换回仓库模式后按原配置检查和运行。

## 定时任务

在 **Superagent → 设置 → 定时任务** 中登记已经确定的例行脚本，例如每五分钟检查邮箱。
填写程序的绝对路径、工作目录、参数、执行间隔和超时；参数框每行代表一个独立参数。
程序通过参数数组启动，Windows 使用隐藏窗口。凭据继续由脚本从受信任的凭据存储或环境中读取，
配置中填写凭据引用或脚本路径。

任务由当前 Superagent 实例运行，配置和执行状态保存在它的状态数据库中。关闭 Superagent
时会停止计时并取消正在运行的命令；重新启动后恢复。停机期间错过多个周期时合并执行一轮。
全局暂停会暂停新的定时触发；恢复处理后继续。同一时间执行一个定时命令，避免检查重叠。

页面提供启停、立即运行、编辑和删除，并显示上次结果和下次执行时间。周期至少 60 秒，
单轮默认超时 120 秒。运行结果记录成功、失败、取消或超时，脚本输出继续由脚本自己的日志保存。
此类已确定的例行检查直接运行脚本，每轮检查无需调用模型。

## Web 来源

Web 来源由插件内置，随个人模式创建默认配置。消息的个人身份由服务端固定为 `owner`，
显示名称为“我”。来源开关与允许名单保存在原有设置体系中；关闭来源或移除 `owner`
授权后，发送入口会说明需要恢复的设置。

任务接口复用 DSH 登录验证、回环地址限制与原有同源管理请求检查：

| 接口 | 用途 |
| --- | --- |
| `GET /orchestrator/api/web/tasks` | 按更新时间和 ID 稳定排序分页列出对话；SQLite 持久摘要索引为列表提供摘要字段，消息正文仅在读取单个对话时加载。已有 KV 对话会在 Store 打开时一次性回填索引 |
| `POST /orchestrator/api/web/tasks` | 交办新的任务 |
| `GET /orchestrator/api/web/tasks/:id` | 读取完整对话和关联工单 |
| `POST /orchestrator/api/web/tasks/:id/messages` | 在原任务中继续交办或追问 |
| `GET /orchestrator/api/web/tasks/:id/artifacts/:artifact` | 下载原对话中已交付的产物快照 |

发送正文为 `{ "text": "任务描述", "requestId": "唯一请求编号" }`。
身份、来源和工单权限由服务端生成与检查。

Worker 通过 `orchestrator_report` 登记产物后，Router 的结果回复会在原任务中显示下载按钮。下载请求复用同源认证，并检查该文件确实交付到当前对话及当前 owner 授权；关闭 Web 来源或撤销授权后会拒绝下载。每个文件最多 50 MiB，返回前校验快照大小和 SHA-256，显示文件名保留中文。按钮显示下载进度状态，失败原因出现在按钮旁，可重新尝试。
