# Personal Assistant 实施与验收计划

基线：`2650d0a`。按用户要求，每个模块冒烟通过后单独提交；每个阶段结束运行更完整的相关测试。阶段成果先在隔离测试环境验证，生产配置由操作者启用。

## 设计约定

- 保留 Engine、Ticket、Assignment、Session、Effects 与 Outbox，个人状态使用同一 SQLite 事务。
- 目标、承诺、事实、约束、注意力、授权和行动记录有来源、时间与 revision，HTTP 更新采用乐观锁。
- 工单复查保存在 Ticket 内，使用原 Session 和原 Mandate；时间到期产生内部输入。
- 长期事实由 owner 确认；模型抽取先保存候选。个人状态工具按 owner 原始请求检查访问，Worker 仅获得关联上下文。
- 受控外部行动绑定精确请求摘要，使用注册适配器执行和核实；结果不确定时先核实。
- 后台通知复用 Outbox 的持久送达回执。暂停、停止、撤权与重启均应保留确定的生命周期。

## 阶段与模块

| 阶段 | 模块提交 | 阶段验收 |
| --- | --- | --- |
| 0 数据基础 | 类型、校验、事务存储、升级与功能设置 | 旧库升级、CAS、回滚、重开、个人数据删除 |
| 1 执行连续性 | 结构化报告；工单复查与取消 | 等待、去重、暂停、停止、授权撤销、重启恢复 |
| 2 个人协调 | 目标/承诺/约束服务；来源可追溯的记忆工具与 HTTP | owner 隔离、期限、冲突、事实候选/确认/替代/过期 |
| 3 注意力 | 通知队列、静默与摘要；Runtime/Outbox 接线 | 时区、午夜、摘要、稳定送达、停止撤销、迟到回执 |

| 5 操作界面 | 个人助理工作台、设置、确认与审计 | 可访问表单、失败保留、分页、审批内容、响应布局 |
| 6 综合验证 | 故障回归、工具接线、使用文档与评估入口 | typecheck、相关集成测试、全套测试、build、浏览器冒烟 |

## 冒烟与阶段测试

模块提交前执行该模块的一小组 Vitest 冒烟；阶段结束补充边界与故障场景，运行关联测试及 typecheck。最终执行 `pnpm check`。记录实际命令和结果，外部服务由本地适配器测试，不使用真实账号发送测试消息。

## 验收场景

1. 交办后记录等待对象和期限，到期只向原工单投递一次。
2. 复查之前停止任务，所有后续复查取消；旧回执保持历史用途。
3. 服务在复查到期、报告提交或 Outbox 投递之间重启，状态与恢复一致。
4. 同一承诺连续更新合并通知；静默时段延后普通提醒，紧急提醒即时到达。
5. 个人事实候选先等待确认；新事实替代旧事实，过期与撤销事实退出默认上下文。
6. 相同时间安排触发冲突提示，并保留所依据的约束。
7. 外部行动显示精确目标与内容，批准后核实；响应丢失后先读取已知送达状态。
8. 非 owner 来源及无关 Worker 访问个人记录时被拒绝。
9. 页面保存与删除使用 revision；并发修改展示冲突并保留用户输入。
10. 停用功能后保留历史、停止新的后台提醒与个人协调动作。
